# Tareas: API Central de Catálogo Global por Rubro para Normalización OCR de Productos

La API central (`catalogo-global-api`) corre con base de datos Postgres y deploy propios, separados de cualquier instancia de cliente (ver `design.md`, Decisión 1) — no vive en `src/` ni comparte base con `consignacion-app`. Las fases 1.x corresponden a ese servicio externo; las fases 2.x corresponden a este repo (`consignacion-app` / `src/`). No hay dependencia dura entre completar 1.x y empezar el scaffolding de 2.x, pero 2.x no tiene nada real que consumir hasta que 1.1–1.4 estén desplegados.

## Notas de secuencia

- La Fase 1 debe estar desplegada y con datos del rubro piloto cargados antes de que la Fase 2 tenga algo real que mostrar — no bloquea empezar el scaffolding del cliente HTTP (2.1–2.4) en paralelo, ya que ese código no depende del contenido del catálogo, solo del contrato del endpoint (que queda fijado en 1.5).
- La evaluación offline (2.10–2.16) es un gate, no un paso opcional: 2.17 (verificación end-to-end en producción) no debería empezar hasta que 2.16 confirme los 3 criterios de éxito del corpus — evita repetir en producción el mismo error que motivó `mejora-precision-lineas-factura-ocr` (confiar en que "se ve bien" sin medirlo).
- El rollout a producción de la Fase 2 debe ser progresivo por instancia (activar `CATALOGO_API_URL` primero en una instancia de prueba, no en todos los clientes a la vez) — ver "Plan de reversión" en `proposal.md`.
- El spike 1.9 debe correr primero y por separado del resto de 1.10-1.17: si la API de Precios Claros no responde como se documentó en `design.md` (es no oficial, sin SLA), hay que reevaluar la fuente de datos antes de construir el resto del sync sobre un supuesto inválido.
- La Fase 3 no se agenda hasta tener señal real de uso de la Fase 2 (cuántas líneas de factura resuelve un candidato global que antes quedaba sin match) — evita invertir en buscador dedicado o clasificación más fina sin evidencia de que la v1 (Precios Claros + heurística de keywords + trigram) no alcanza.
